# Wildlife Atlas

iOS-приложение для просмотра наблюдений за дикой природой из публичного [iNaturalist API](https://www.inaturalist.org/pages/api+reference).

Решение тестового задания для стажёра iOS (осень 2026): лента наблюдений, детали, поиск и фильтры по таксонам, плюс дополнительные фичи из ТЗ.

## Возможности

### Экран списка (Explore)

- Первая страница последних публичных наблюдений при открытии
- Всегда `captive=false` — только дикая природа
- Карточка наблюдения: фото, общепринятое и научное названия, дата, отметка качества
- Постраничная подгрузка при прокрутке
- Переключение режимов **список / плитка**
- Поиск таксона с автодополнением; выбранный таксон становится фильтром
- История последних **5** выбранных таксонов (до начала ввода)
- Три независимых фильтра:
  1. Таксон — все наблюдения или выбранный вид
  2. Качество — любое или research grade
  3. Порядок — сначала новые / сначала старые (по дате наблюдения)
- Состояния: загрузка, контент, пусто, ошибка с повтором

### Экран деталей (Observation)

- Открытие по числовому `id` наблюдения
- Фото, названия, качество, дата, таксономия, место, автор
- Место скрыто для private / obscured наблюдений (без координат и геолокации)
- Возврат к ленте с сохранением данных, фильтров и позиции скролла
- Галерея всех доступных фото наблюдения
- Share текущего наблюдения

### Дополнительно из ТЗ

- Кэш изображений в памяти (`NSCache` + дедупликация in-flight запросов)
- Локальные закладки (вкладка Bookmarks)

## Требования

- Xcode 15+ (рекомендуется актуальная версия)
- iOS **16.0+**
- Сторонних зависимостей нет
- Сеть: только `URLSession`
- Авторизация в iNaturalist не нужна
- Вёрстка адаптивная: интерфейс рассчитан на все размеры экранов iPhone (от компактных до Pro Max), без привязки к фиксированной ширине конкретного устройства

```
│   ├── Explore/          лента, поиск, фильтры, список и плитка
│   │   ├── Models/       ObservationQuery и фильтры
│   │   ├── ViewModels/   ExploreViewModel, TaxonSearchViewModel
│   │   └── Views/        экран, карточка, плитка, фильтры, поиск
│   ├── Detail/           детали наблюдения, галерея, таксономия
│   │   ├── ViewModels/   ObservationDetailViewModel
│   │   └── Views/        экран деталей, галерея, таксономия
│   └── Bookmarks/        локальные закладки
│       └── Views/        экран закладок
├── Shared/
│   ├── UI/               тема, RemoteImage, состояния, бейдж качества
│   └── Utilities/        даты, форматтеры, ImageLoader
└── Resources/            Assets.xcassets
```

Верхний уровень разложен по слоям: `App` — точка входа, `Core` — данные и сеть,
`Features` — экраны (внутри каждой фичи разделение на `Models` / `ViewModels` / `Views`),
`Shared` — переиспользуемые UI-компоненты и утилиты.

MVVM: экраны опираются на `ObservableObject`-вью-модели, сеть спрятана за протоколами `INaturalistService` / `HTTPClient`.

## Ключевые решения

### API v2 и `fields`

Используется `https://api.inaturalist.org/v2`.

В v2 можно явно запрашивать нужные поля через `fields`. Это сильно уменьшает размер ответа по сравнению с «толстым» v1: для ленты достаточно превью и базовых полей таксона, для деталей — фото с атрибуцией, user и uri.

Детали открываются запросом `observations?id=…`, а не путём `/observations/{uuid}`: в ленте приходит числовой `id`, а путь v2 ожидает UUID.

### Фильтры и пагинация

`ObservationQuery` хранит три независимых фильтра. Любое изменение сбрасывает страницу и перезагружает ленту с учётом остальных значений.

- `captive=false` всегда
- сортировка по `observed_on`
- дубликаты между страницами отфильтровываются по `id`
- устаревшие ответы игнорируются по номеру «поколения» запроса (быстрая смена фильтров / отмена)

### Поиск таксона

Автокомплит идёт в `taxa/autocomplete` с debounce. Выбор таксона выставляет фильтр «Таксон». Пока пользователь вводит запрос, лента может временно показывать наблюдения по найденным таксонам; после выбора закрепляется один фильтр. Недавние таксоны хранятся в `UserDefaults` (лимит 5).

### Состояния и навигация

`NavigationStack` + value-based переход по `WildlifeObservation.ID`. Экран деталей живёт отдельно от ленты, поэтому возврат назад не сбрасывает уже загруженные страницы, фильтры и скролл.

На экранах: loading / content / empty / error + retry. Ошибка следующей страницы показывается в футере, без очистки уже загруженного списка.

### Адаптивная вёрстка

Интерфейс собирался так, чтобы корректно выглядеть на всех экранах iPhone: гибкие стеки и сетки, `maxWidth` / пропорциональные отступы, без хардкода под один размер. Список и плитка, карточки, детали и sheet галереи подстраиваются под доступную ширину и safe area.

### Приватность места

Координаты не запрашиваются и не показываются. `place_guess` скрывается, если наблюдение private/obscured или помечено `obscured`.

### Качество наблюдения

В API приходит `quality_grade` (`research` / `needs_id` / `casual`). В UI на карточках это отображается как отметка A/B/C; на экране деталей — текстовый pill («Research grade» и т.п.).

### Изображения и офлайн-данные

- `ImageLoader` (actor) + `NSCache` для in-memory кэша
- закладки сериализуются в JSON в Application Support
- история таксонов — в `UserDefaults`
