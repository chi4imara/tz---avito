# Использование AI-инструментов

AI использовался как вспомогательный инструмент для ускорения разработки. Архитектуру, разбор ТЗ, ключевые решения по API и основную реализацию экранов/сетевого слоя вёл я; модели помогали быстрее набирать шаблонный код, искать подсказки по API и закрывать рутину.

## Инструменты

- **Cursor** (агентный режим) — подсказки по коду, рефакторинг отдельных кусков, генерация тестов и черновика документации
- **curl** / документация iNaturalist — проверка ответов API руками

Модель в Cursor: Composer / агентный ассистент среды Cursor (версия среды на момент выполнения задания).

## Для каких задач использовался AI

1. **Ускорение рутины** — заготовки SwiftUI-вью, однотипные модели `Codable`, повторяющиеся состояния loading/empty/error.
2. **Справка** — уточнения по iNaturalist API v2 (`fields`, пагинация, `taxon_id`, форматы дат).
3. **Отладка** — поиск причин отдельных compile/runtime проблем (ATS/entitlements, iOS 16 availability, пустой `TabView` в sheet, layout фото в карточках).
4. **Тесты** — генерация каркаса юнит-тестов и фикстур JSON.
5. **Документация** — черновик `README.md`.

Решение собиралось итеративно, с ручной проверкой поведения на симуляторе и сверкой с ТЗ и референсами.

## Ключевые промпты (по смыслу)

Кратко, без дословных логов — запросы были прикладные:

- «Разбери ТЗ и что обязательно / дополнительно»
- «Как в iNaturalist v2 запросить наблюдения с `fields` и `captive=false`»
- «Почему `ContentUnavailableView` / `@Observable` не подходят под iOS 16»
- «Почини пустую галерею в `.sheet`»
- «Сгенерируй юнит-тесты на ExploreViewModel / decoding / persistence»
- «Напиши README по ТЗ»

## Что сделано мной

- Понимание ТЗ, объём обязательного и дополнительного
- Выбор API v2 и стратегии `fields` / запроса деталей по числовому `id`
- Структура проекта (Features / Networking / Persistence / MVVM)
- Логика ленты: фильтры, пагинация, поколения запросов, сохранение состояния при возврате с деталей
- Поиск таксона, история последних 5, закладки
- UI по референсам (карточки, бейдж качества, детали, галерея, share)
- Ручная проверка сценариев на симуляторе и правки после прогонов

## Что сделано с помощью AI (с моими правками)

| Часть | Роль AI | Мои правки |
|---|---|---|
| Юнит-тесты (`WildlifeAtlasTests`) | Сгенерировал каркас тестов, stubs, fixtures | Подправил кейсы под реальный API/модели, убрал лишнее, прогнал `xcodebuild test` |
| `README.md` | Черновик по структуре ТЗ | Сократил/уточнил формулировки, сверил с фактическим кодом и требованиями |
| Отдельные UI/сеть куски | Ускорил написание однотипного кода | Встраивал в общую архитектуру, правил стиль и edge cases |

## Что отклонено / не принято из предложений AI

- Поднимать deployment target до iOS 17 ради `@Observable` / `ContentUnavailableView` — нужно было iOS 16
- Оставлять Push Notifications / Background Modes / ATS Allow Arbitrary Loads «на всякий случай» — для приложения не нужны
- Локальный HTTP-прокси / DEBUG-подмена URL под среду агента — для сдачи решения не требуется
- Имя модели `Observation` — конфликт с системным модулем Observation; оставлено `WildlifeObservation`
- Избыточные абстракции и «генераторный» UI, не совпадающий с референсами — переписывал под макеты ТЗ

## Итог

AI помог быстрее закрыть тесты, документацию и часть рутины. Ядро приложения (архитектура, сеть, экраны, поведение по ТЗ) проектировалось и доводилось мной; без ручной сборки, проверки на симуляторе и сверки с заданием результат к сдаче не готовился.
